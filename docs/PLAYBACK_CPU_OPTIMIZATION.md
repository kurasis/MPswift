# Playback CPU work (2026-10-14)

The owner reports increased CPU only while playing and authorizes all four proposed improvements. Baseline application source is `c0debc6cf51409a30d449968bcb3512d68e376a3` (published 1.0.141-dev.1). No physical-device profile or percentage is available; source findings identify avoidable work rather than establish its share of that machine's CPU.

| Area | Confirmed source work | Change |
| --- | --- | --- |
| `PlaybackCoordinator` / `PlaybackOrder` | Each playing snapshot builds the full candidate array to read only its first entry. | Track preparation dirtiness at source/order/load/seek changes; use an equivalent first-candidate lookup without materializing remaining candidates. Existing full traversal and public interfaces remain. |
| `PlayerViewModel` | Position ticks reformat stable labels; assigning `Format` then repeatedly appending its bit/output suffix produces intermediate property changes every tick. | Cache label inputs, assign the final format once, format elapsed seconds only when the displayed second changes, and notify transport availability only when it changes. Every engine snapshot still reaches listening/error/state handling; exact seek position remains. |
| `WaveformAccumulator` / `WaveformControl` | Bucket division and array updates occur for each PCM frame/sample; subpixel cursor updates invalidate the entire drawing. | Accumulate contiguous bucket spans in locals, retaining sample/addition order and invalid-input checks. Invalidate playback drawing at physical-pixel changes and seek endpoints; precise position, mouse preview, keyboard/UIA, cached geometry and native decoding remain. No samples are omitted and analysis is not deferred or rate-limited. |
| `PlayerViewModel` / `SqlitePlayerStore` | Periodic session saving captures and validates every playlist even when only position/settings change. | Use an internal optional session-write capability with session validation, bounded JSON and the existing serialized transaction. Full library changes still capture/validate/write the library; external `IPlayerStore` implementations retain their full-state fallback. Settings saving and the ten-second interval remain. |

Locked local baseline: 345 Core pass, CLI 78 pass/15 Windows-only skips, zero build warnings/errors. Changed-source checks: 366 Core pass and unchanged CLI counts. Targeted controls compare candidate results and shuffle-refill state against full traversal for all repeat/shuffle modes and queue/removal/restoration, verify bounded tick allocations and change/seek invalidation, compare PCM extrema/RMS exactly with the original frame calculation, and reopen a 10,000-entry SQLite library after session writes guarded by triggers against any library-row modification. Invalid sessions preserve prior data.

Required real Windows `PlaybackPerformance` smoke measures full-vs-first candidate allocations/wall time/process CPU milliseconds on the same host, stable UI property notifications with controlled position updates on an actual paused source, optimized session writes without library captures, and real WPF waveform invalidations for a three-minute visual timeline. Allocation/semantic/invalidation controls are gates; wall/CPU timings are measurements rather than flaky timing thresholds. Native decode, existing gapless/CUE/audio, source hashes, shutdown, installed EN/RU and per-user installer gates remain mandatory. The controlled measurements do not establish overall playing-device CPU savings on the owner's PC. Physical WPR/CPU sampling and before/after Task Manager comparison on the same cached track/device are remaining hardware acceptance.
