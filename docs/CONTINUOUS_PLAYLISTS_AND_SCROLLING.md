# Continuous playlists and scrolling (2026-10-15)

The owner requests automatic continuation after an album and explicitly confirms continuation into subsequent playlists. Playback already traverses album headings within its complete source independently of search. It now continues forward through tab order after that source is exhausted, skipping empty/disabled/unavailable sources, and stops after the final playlist. Existing Repeat One and Repeat All retain their track/current-playlist scopes, explicit queue precedence, shuffle-without-replacement, actual-playback history, manual Stop/Next behavior and output-error policy remain. File/decoder failures can proceed to later sources within a bounded traversal; output failures require explicit retry. A detached/deleted source never jumps into an unrelated playlist. No wrapping between playlists is added.

`PlaybackCoordinator.Playlists.cs` receives immutable UI-published playlist order snapshots. The engine never reads WPF collections or blocks on the dispatcher. Ordinary natural end resets only the next playlist cursor/shuffle remainder; history and queued snapshots remain. Native preparation can stage the first eligible song of the following playlist; transition adopts its source before preparing the next song. Source identity belongs to the coordinator, so browsing or updating another tab cannot restore an outdated source while UI delivery is pending. Source/active/order session capture is atomic. Reordering tabs republishes continuation order. The browsed tab remains selected; now-playing source and session identify the actual automatically chosen playlist. Public interfaces, session schema, dependency pins, native decoding/output, music bytes and safety protections remain unchanged.

The scrollbar paints a 4 DIP line in the existing 12 DIP hit target, retains the 36 DIP minimum thumb geometry and native full-range/keyboard/UIA scrolling, and increases contrast on hover/drag. `SmoothPlaylistListBox` uses pixel scrolling with recycling still enabled. Wheel deltas accumulate into an interruptible 180 ms ease-out; fractional wheel deltas are retained and Windows wheel-line/page settings are respected. Keyboard, mouse, touch, selection, drag, source/filter changes, hidden/unloaded controls and template replacement cancel the animation. `SystemParameters.ClientAreaAnimation` disables movement animation. Rendering is subscribed only during active motion, with work capped near 60 updates/second; no idle polling/timer is added. This targets playlist wheel scrolling; tab navigation and native touch/scrollbar mechanisms retain their existing behavior.

Current Vercel web-interface guidelines were fetched over verified HTTPS and reviewed for native-applicable behavior: retained keyboard/UIA semantics, focus/navigation alternatives, reduced motion, interruptibility, hover/drag contrast and large-list virtualization. Browser DOM/ARIA, URL, hydration and CSS-specific rules do not apply to WPF. Twelve Core regression cases cover album/source boundaries, long-source cursor reset, prepared transitions, queue/history, repeat/shuffle, edited tab order, detached/manual-stop behavior and decoder versus output failures. Owned Windows `PlaylistScrolling` checks the actual template, painting/hit geometry, controlled intermediate frame offsets and reduced motion, routed high-resolution wheel input, interruption, full range, ScrollIntoView/recycling and hidden/filter cleanup. Controlled elapsed frame samples are not physical wheel/touch latency measurements. Existing real native and installed/portable EN/RU acceptance gates remain mandatory before publication.
