# Security follow-up: native parsers, file continuity and resource bounds

The owner authorized items 2–4 from the end-user audit. Baseline source `72d27cd1559603b1ec6aa3cb1937066d70630681` passed 228 tests on Linux/Windows and [main CI 37587964025](https://github.com/kurasis/MPswift/actions/runs/37587964025), including EN/RU and extracted package checks. Source was inspected before execution. New malformed native inputs are executed only in disposable Windows CI or an explicitly configured isolated lab, never on a working PC. Application APIs, dependency versions, formats, normal launch, installation and update policy are retained.

## Implemented native test workflow

`scripts/Security-Smoke.ps1` and `tools/Player.AudioSmoke/ParserSecurityValidation.cs` add a deterministic 56-case corpus: 14 synthetic seeds covering WAV/AIFF/FLAC/MP3/Vorbis/Opus/ALAC/AAC/WMA/WavPack/TTA/DSD/APE/Musepack, each with a valid control, truncation, fixed-seed header-bit mutation and declared-size mutation. The tracked source fixtures are never modified. Mutants and a tool copy exist only in a fresh token-named workspace. Seed/mutant SHA-256, outcomes, native decoder facts and peak committed memory are retained in `artifacts/smoke/security-parsers.json`.

Each case uses a fresh actual decoder process. `SecurityChildProcess.cs` assigns a Windows Job Object before the worker can pass its stdin handshake: 512 MiB process committed-memory limit, eight seconds user-mode CPU, one active process, kill on job close, fifteen seconds wall deadline, and bounded stdout/stderr. Job membership and configured limits are queried back. A waiting-worker control verifies deadline cancellation, termination and waiting for the exact owned process. Failures, access violations, timeouts, memory-limit exits and unexpected exit codes fail the suite; they are never counted as successful format rejection. A normal format rejection must also reopen/decode the valid WAV control in the same worker. Valid originals and decoded/rejected mutant bytes must remain unchanged; file handles must release.

This is short deterministic mutation testing, not coverage-guided fuzzing. The Job Object limits resources; it does not restrict the worker's filesystem/network rights or replace a disposable VM. The test is gated to disposable CI or `MPSWIFT_ISOLATED_SECURITY_LAB=1`; that variable acknowledges an operator-provided lab and is not proof of isolation. It introduces no player CLI, server, recorder or network request. Native component provenance/advisory limitations from the original audit remain: no unsupported CVE is assigned to a closed addon.

## File and DLL findings and fixes

### SEC-06 — Hash verification/load gap (medium, conditional local code execution)

- Files: `Services/Audio/NativeLibraryBootstrap.cs`, verification loop and subsequent core/decoder loading; `NativeDecoderPlugins.cs`, PluginLoad.
- Conditions: another process can modify/replace a writable packaged native DLL between the former File.OpenRead hash check and loading. Optional decoders were checked before they were loaded later. An attacker with write access can target that gap; this does not independently elevate privileges.
- Damage: loading different executable bytes from those checked, with the player's existing rights.
- Fix: `LocalReadLease.cs` opens read-only with share-read only, inspects actual handle attributes/link count, resolves its local canonical path and pins its directory chain without delete sharing. Native files cannot be file/directory reparse aliases or hardlinked. Successful DLL pins are retained for process lifetime; failed prevalidation releases that attempt's pins. The native manifest is bounded to 64 KiB/depth eight/13 identities with consistent core/decoder roles. Load the verified canonical path, preload optional decoders through the same loader, and retain the existing optional-dependency error behavior.
- Dependency search: explicit NativeLibrary.Load System32 search flags exclude CWD/PATH/native-folder shadows for static imports; the approved BASS core is already resident for addon imports. This is a scoped loader policy, not a silent process-wide SetDefaultDllDirectories change.
- Test: a worker first confirms an owned FLAC DLL is writable without writing bytes, then verifies all ten optional decoder DLLs refuse write access before PluginLoad. All 13 approved modules must resolve under the owned tool copy. Inert winmm/msacm32/shlwapi/msvcrt shadows are placed in CWD and the native directory; actual dependency module paths must resolve to System32. No planted test DLL contains executable code.

### SEC-07 — Path checks separated from parser open (medium, conditional integrity/availability)

- Files: `BassMixerGraph.OpenSource`, `BassSmokeSession.Decode`, `BassWaveformService.Decode`, `MediaMetadataReader.Read` and `LocalFileAccess` validation followed by a path-based parser open.
- Conditions: another process renames/repoints a mutable path or writes through a hardlink during the validation/open window. A validated pathname alone does not guarantee the next open sees the same local object.
- Damage: unexpected parser input, stale facts, availability failure or redirection outside the intended local path. No arbitrary deletion/source write is introduced by the player.
- Fix: acquire the local read lease, verify the opened handle, resolve its local path, pin the resolved directories and recheck that the handle path is unchanged. Pass that canonical path to the parser. Hold the lease for metadata/waveform/decode scope and production source opening/format inspection. Local media symlinks/junctions continue to resolve locally; native executable aliases are refused. Typed FileUnavailable errors are retained.
- Test: `RestrictedFileSecurityValidation.cs` disables the Administrators group and maximum privileges for synchronous file/loader checks, confirms the effective principal, and invokes `NativeFileSecurityValidation.cs`. The fresh owned lab root grants the current user explicit access, making write-denial checks independent of Admin ACL access. The lab prepares links before privilege removal; consuming links needs no symlink-creation privilege. Source write/rename, directory rename and hardlink-alias writes must fail while pinned, then source write access must reopen without changing bytes after disposal. Existing local media links work; native hardlink/file-link/directory-link paths fail.
- Boundary: this is an effective restricted token for synchronous operations, not a separate standard-user Windows 11 installation or a restricted primary token for every native background thread. No accounts, services, registry or system ACLs are changed. Only the fresh lab root receives an explicit ACL.

## Resource findings and fixes

### SEC-08 — Backup directory materialized before entry-count rejection (medium availability)

- File: `BackupBundle.ExtractValidated`, formerly ZipArchive.Entries.Count before enforcing three entries.
- Conditions: an input ZIP within the existing archive byte bound contains many central-directory records, or claims three while supplying more.
- Damage: unnecessary object/string allocation and parsing work before the expected rejection; existing exact names and hashes already prevented arbitrary restore destinations.
- Fix: `BackupZipDirectory.cs` reads at most 65,557 tail bytes and three fixed 46-byte central headers before constructing ZipArchive. Verify one disk, exactly three entries, bounded directory size/offsets/header spans, exact consumed directory end; preserve valid ZIP64 and comments. The 512 KiB directory cap accommodates the ZIP maximum extra/comment fields for three allowed entries. Existing body/hash/database preservation checks remain.
- Tests: 10,000-entry rejection after only the bounded tail; false three-entry count cannot hide a fourth record; valid three-entry/ZIP64 streams reset and open normally; existing complete-backup/rollback tests remain.

### SEC-09 — Expensive SQLite schema/VM work (medium availability)

- Files: `DatabaseRecovery.Validate`, `SqlitePlayerStore.Open` and queued database actions. Existing cell bounds did not bound schema enumeration or SQL work.
- Conditions: a crafted valid data DB/backup contains excessive schema or expensive VM work (including a trigger reached on saving). The application does not interpolate user SQL, but a SQLite data file can contain executable schema definitions.
- Damage: a blocked DB owner, high CPU and queued operations; no SQL injection or code execution is established by this finding.
- Fix: per-connection SQL text <=1 MiB, columns <=256, expression depth <=100 in addition to the existing 49 MiB row limit. Before quick_check, enumerate at most 129 schema objects and reject more than 128, names over 256 characters or definitions over 64 KiB. Existing supported application schemas fit these limits. `DatabaseValidationBudget.cs` installs an owned progress callback every 1,000 VM instructions: at most 500 million approximate VM instructions/one minute per validation or queued operation, then SQLITE_INTERRUPT. Scope disposal removes the callback. SQL limits apply to SQL text, not the existing bound JSON parameters/session size. No global SQLite heap setting is changed.
- Tests: small instruction/time-budget interruption followed by a successful query on the same connection; oversized schema rejected with unchanged DB hash; actual production SaveAsync into an owned billion-step recursive trigger is interrupted with code nine, rolls back and leaves the committed session readable on the same store. Ordinary valid store/index/migration/backup cases continue to pass.
- Boundary: a VM callback is cooperative, not a hard total process-memory/CPU sandbox. It cannot preempt a long single native function, every startup allocation, OS I/O or SQLite BackupDatabase page copying. Archive/database byte caps and preservation apply separately.

## Local checkpoint and remaining work

Malformed SQLite/ZIP checks use bounded synthetic data in the isolated cloud workspace. Native/file/impersonation tests require this source's disposable Windows CI; its JSON evidence and source commit are retained with the successful separate GitHub build.

Residual checks include coverage-guided/native sanitizer fuzzing and decoder/image/sidecar variants, closed-addon internal dynamic LoadLibrary behavior, parser reads after the production source-opening lease ends, mutable WavPack correction companions, SQLite initialization allocations and uninstrumented native functions, and concurrent replacement of mutable application data directories outside the scoped parser leases. Host patching/clean Windows 11/device acceptance and publisher signing remain separate. Same-user code can attack a writable installation before startup or modify trusted unsigned manifest metadata; read continuity and hashes do not authenticate the publisher. These fixes do not establish full application safety.
