# Architecture — Stage D/E

Two production projects are established. `Player.Core` contains pure C# rules, with no WPF, native, database or dispatcher references. `Player.App` owns WPF presentation and platform services. The core includes offline local-path/segment rules, audio contracts, serialized engine state and sequential playback coordination. Actual drive type/cloud state checks stay in Windows code; lexical validation alone does not prove a file is local or hydrated.

The WPF composition root injects `IAudioPlayer`, its coordinator, import/dialog services and the dispatcher into `PlayerViewModel`. Views contain layout/input mechanics; native ownership stays in the engine. Startup does not open BASS or an endpoint, so users can browse/import even when playback dependencies are unavailable. Storage, waveform and paged library interfaces are implemented.

`Player.AudioSmoke` is a CLI development harness that links the same native loading/session/backend source as the app. It is not a third production layer, and `BassSmokeSession` is not the production playback engine. Native mutations are synchronous and owned by the calling command thread. Its persistent decode mixer renders float PCM to shared WASAPI in the negotiated endpoint mix format. The retained Stage A `--play` harness uses source gain 0.1; Stage B `Smoke.ps1 -Play` exercises the actual production backend/app gain instead; generated tone amplitude is 0.05. Current Stage D DSP/gain policy is described below.

The output callback has a strongly retained delegate, performs native decode and bounded atomic counters, and records failures for the command thread. It performs no logging, SQL or UI work and does not propagate managed exceptions. Output is freed/quiesced before mixer/source/BASS teardown. A teardown failure is surfaced rather than freeing a potentially live graph. Loaded libraries live for the process lifetime and are not unloaded while P/Invoke stubs can still reference them.

`NativeLibraryBootstrap` validates exact approved files against the manifest before loading. A resolver maps ManagedBass imports to already-loaded absolute paths under the application directory. It does not search working directories, media folders or PATH. Packages and official archives are separately pinned. Runtime capability claims require Windows execution, not merely hashes or compilation.

The fixture generator emits a small PCM16 WAV, known-duration/peak/channel manifest and checksum. Decode checks exercise end-of-file and midpoint seek; output checks exercise source consumption, pause/resume and stop reset. They do not measure the audible timeline or gapless boundaries. Source SHA-256 and an exclusive read-only reopen check preservation and handle release.

Implemented production threading: short dispatcher updates, serialized native engine commands, bounded realtime callbacks, a bounded metadata worker, and generation/revision checks to reject stale results. Database/settings/waveform/cache and persisted queue/history/index are implemented through Stage E; all SQLite work remains on the bounded database owner.

## Historical Stage B production slice

`SerializedAudioPlayer` owns a bounded command queue and dedicated native-context thread. Factory/open/play/pause/seek/dispose run on that owner; no native mutation occurs in WPF handlers. Immutable snapshots carry load generations and publication revisions. Coalesced pending loads/seeks replace obsolete work; stopped/disposed generations cannot autoplay after an older decode completes. A 100 ms engine poll runs only during playback; there is no permanent UI polling timer.

`PlaybackCoordinator` owns full entry order independently of the filtered WPF collection and remembers actually started entries. Track identities may be shared by duplicate occurrences; entry identities never are. Removing a playing row retains active metadata/playback and the next source position. Stage D adds queue/repeat/shuffle and persistent output scheduling.

`BassAudioBackend` owns decoder/plugins/source/mixer/shared WASAPI, strongly retains its callback, and quiesces output before freeing resources. The callback only reads float mixer data, applies smoothed linear app gain/mute and signals native errors through atomic fields. Source position uses mixer history adjusted for the WASAPI buffer. No callback allocations, I/O, logging, UI calls or blocking locks. The historical Stage B graph closed/rebuilt output for track/seek boundaries, so it makes no gapless claim.

`MediaImportService` validates local paths before reads, skips reparse/offline folder recursion and emits bounded batches from one background metadata worker. TagLib failures use real filenames and bounded details; no fake artwork/tags/waveform. `PlayerViewModel` marshals snapshots through the dispatcher with revision rejection; views handle input/layout only. Import does not autoplay. Resource-owned shutdown awaits import and audio disposal.

## Stage C persistence and waveform

SQLite operations run synchronously on one bounded dedicated owner thread; every multi-entry/tab snapshot is a transaction and periodic session-only saves do not rewrite playlists. Foreign keys/WAL/3-second busy timeout are explicit. Schema 1 is the initial persistent schema; incompatible existing/newer databases are preserved and rejected. A per-directory ownership file prevents conflicting app writers. Backup uses SQLite BackupDatabase with live WAL; explicit recovery validates first and preserves main/WAL/SHM originals. Session stores selected tab separately from playback-source tab plus stable active-entry snapshot/position, including detached removed entries. On restore, native Prepare/Seek are allowed and Play is never submitted. The selected tab and active source are distinct, and the header identifies the latter. Obsolete waveform display/progress is cleared as loading starts.

Settings JSON has schema/range validation, debounce, fsynced temporary write and atomic replace with a previous backup. The view model records bounded session checkpoints and awaits final saves before stopping audio. Tab view selection never substitutes the filtered collection for the coordinator source. Tab/row edits preserve stable IDs, with manual reorder rejected under search.

The one waveform worker owns its independent decode-only float stream. Process-wide BASS device/plugins are reference-counted, and each owner selects its thread-local no-sound context. An analyzer cannot free the playback graph. Fixed-size frame chunks aggregate minima/maxima across all channels; signed summation is deliberately avoided. Finest buckets target 100/s and coarsen for long media, bounded at 300,000 buckets (2.4 MB peak payload). No full-file PCM allocation and no playback gain/EQ are applied. Native manifest + canonical path/size/mtime/algorithm identify the completed peaks cache; corruption/oversize/source changes cause regeneration or a visible unavailable state.

A custom WPF control caches one frozen geometry when peaks/size change and clips the played overlay per position. A real slider remains available while analysis is pending or fails. New analysis requests supersede obsolete work; UI generations reject stale progress/results. Cache is disposable and separate from library/settings data.


## Stage D/E coordination and file workflows

`PlaybackOrder` owns snapshot queue occurrences, a separate playlist cursor, randomized stable-ID bag and bounded actual-start history; `PlaybackCoordinator` resolves/invalidates the single prepared successor. `SerializedAudioPlayer` adopts native incoming requests on the audible timeline without submitting a new UI-timer load. `BassMixerGraph` schedules limited sources in output-frame bytes inside one persistent decode mixer. Owner mutations lock the native mixer; render callbacks do no UI/database/file-open work. Endpoint changes/recovery pause and keep context, with no silent exclusive fallback.

Actual gain order: decoder → track ReplayGain and BASSmix equal-power envelopes → resampling/mixing → master 10-band biquads with conservative headroom/preamp → app gain/mute → final hard full-scale saturation → WASAPI. Coefficients are constructed on the owner and the callback blends previous/new processing for 20 ms. Final saturation is disclosed; this graph is not advertised as bit-perfect. Waveform uses an independent unprocessed decoder/cache and segment clipping.

Schema 2 adds separate roots/index/statistics/listening records and playlist date-added ticks, with a real schema-1 backup before transactional migration. All writes stay on the existing bounded database owner. Scanning has a 256-path producer/one metadata consumer/64-file transactions; source size/time determines tag rereads. Complete scan generations mark missing availability without deleting logical metadata or ratings. Watchers debounce hints and overflow into reconciliation, ignoring app DB/cache files. Library substring search uses normalized Unicode columns with parameterized `instr` and bounded pages; WPF holds only the current page.

Metadata and images are read-only/local. Artwork uses a single worker and bounded frozen thumbnails. Listening counts wall-clock playing intervals rather than seek distance, records occurrences idempotently and caps recent persistent history at 1,000. M3U8/PLS parse bounded local references; recursive/network references are rejected. Export is atomic and refuses CUE loss; relink validates through an independent native context, then updates logical snapshots while retaining IDs. No command deletes or rewrites music.

## Stage F Windows ownership

`SingleInstanceService` owns the user-SID-scoped global mutex on the startup UI thread. The server uses `CurrentUserOnly`, bounded framed JSON and a 32-item channel; its consumer waits for initialization and dispatches serialized imports to the active model. Secondary processes forward and exit before opening storage. Only explicit `--play` starts audio.

`MediaSessionService` uses desktop HWND SMTC with one event subscription and coordinator commands. It publishes the model's actual state/metadata and bounded local thumbnail, and unregisters on exit. `TrayService` observes that same model; hiding does not own/dispose playback. Close-to-tray is opt-in. Startup selects a persisted English/Russian culture before creating UI. Language requires restart to avoid partially switched static XAML resources. Theme brushes are dynamic for high contrast; custom waveform provides RangeValue Automation.

## Stage G reviewable output and diagnostics

`RotatingLog` accepts at most 128 bounded UTF-8 JSON entries without blocking callers, serializes file I/O on its worker, rotates five 2 MiB files, and reports dropped/write-failed diagnostics. Startup/operation details redact known personal/app/data prefixes; position/audio callbacks are not logged. Shutdown awaits its bounded drain. Help opens a local read-only scrolling window, never a browser.

`Strings.Culture` is selected once from settings before creating UI. Resource lookups/display formatting use this explicit culture because IPC/dispatcher continuations can carry a different ambient culture. Restart is required for a language switch. First database initialization accepts a parameterized localized default name; persisted user names are preserved.

Candidate packaging publishes into a new GUID-owned stage rather than copying possibly dirty prior output. Per-file hashes/size, source commit/dirty state, all required framework/native files/companions, available NuGet declarations/notices and explicit development-only marker are audited. Self-referential manifest/checksum exclusions are explicit; the outer ZIP has a separate checksum. Negative checks mutate only an owned extracted copy. CI retains JSON/TRX/screenshots/checksums as evidence and, on main builds, a separate Windows ZIP artifact for owner-authorized development prerelease publication. Package smoke runs the extracted apphost from a Unicode path/different directory; hosted SDK presence still prevents a clean-machine claim.


## Complete backup and measured development workflows

`BackupBundle` takes a supported SQLite live-WAL backup and validated settings into a fresh owned staging directory. A flushed no-overwrite ZIP contains only those two files and a versioned size/hash manifest. Restore extracts only exact expected names into a bounded owned stage, validates SQLite/schema/foreign keys plus the real saved-state loader and settings, and holds destination ownership while retaining original files and installing the pair. Partial installation failures roll back moved originals; failure to reopen saved files exits rather than manufacturing defaults. Installation is rollback-protected across the pair, not a claim of power-loss atomicity across multiple file renames. The WPF restore path suspends tray/SMTC, stops/disposes the old model, recreates the actual model, rebinds integrations and makes IPC wait for restoration. Legacy database-only restore remains explicit.

The explicit development UI smoke also runs owned filesystem ACL/lock/artwork checks and production search/page/scroll measurements. The 100k dataset is synthetic indexed metadata seeded into actual SQLite, not a scan of 100k physical music files. Raw timings and process CPU/resource context are recorded separately from Windows 11 reference-hardware acceptance; no forced GC hides memory samples. Functional paging/virtualization assertions are required even when a timing budget is missed. Large portrait thumbnails decode by their larger dimension and remain at most 192 pixels on either side.
