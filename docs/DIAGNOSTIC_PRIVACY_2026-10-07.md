# Diagnostic path privacy regression

Baseline: `f689fdc038c8`; locked Release build passed 249 tests with zero warnings/errors before edits. Static inspection preceded targeted synthetic-data checks; no private owner data or potentially dangerous installer/native script was run locally.

## SEC-15 — Configured private paths remain visible in alternate string forms

- Files/sections: `Player.Core/Integration/DiagnosticReport.cs` prefix preparation; `RotatingLog.cs` constructor/Record; `PlayerViewModel.CreateDiagnosticReport` caller-side JSON prefix handling.
- Finding: report replacement required the literal configured prefix. The WPF caller handled default JSON escaping but not forward-slash path strings inside error/detail values. The log handled literal prefixes only, including neither JSON-escaped values nor forward-slash variants; Operation was unredacted. Configured trailing separators also prevented some otherwise equivalent forms from matching. Four of six initial regression cases failed on the baseline: three report representations and a log record. The baseline app report's ordinary default-JSON path form was already handled by its caller; this is not claimed as a new leak there.
- Conditions/damage: an error/detail contains a configured personal path using an alternate representation, or an API caller puts it in Operation. It can remain in local diagnostics/logs and reveal a username/location if the user shares those files or copies the preview. Logs/report creation do not send data automatically; no command execution, PC compromise or password leak is established.
- Risk: low, conditional confidentiality. The path must appear in a diagnostic string and someone must obtain the resulting local report/log. This is narrower than arbitrary secret removal.
- Minimal fix: prepare plain/backslash/forward-slash and default JSON-escaped prefix variants centrally, trim trailing separators before encoding and match longest first. Logs retain their existing conservative substring replacement and queue/file/field limits, now applying it to both fields. Reports retain existing directory-suffix matching and the 32768-character/Unicode boundary. The WPF caller supplies ordinary prefixes rather than duplicating JSON preparation. Public signatures, JSON schemas, dependency versions, source music and network behavior are unchanged.
- Regression checks: four plain/JSON/slash report cases; four log cases including nested valid JSON and Operation; similarly named report directories remain visible; existing nested-prefix/case/Unicode/truncation and log-rotation/error tests remain. Test files are owned temporary directories removed after disposal.

This completes this specific prefix-representation defect, not a guarantee that every diagnostic string contains no personal information. Unconfigured locations, metadata, arbitrary exception text and secrets can still be private. Preview before sharing. Latest source build and Windows/package results must be observed separately; earlier CI is only the baseline.
